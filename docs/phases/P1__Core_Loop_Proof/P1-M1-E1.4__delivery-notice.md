## Decisions settled during execution (per spec Execution Notes)

1. **Assistant/tool message shapes appended per round** (both modes; the model sees its own prior turn as it emitted it):
   - *Native mode:* the assistant message is re-sent with `tool_calls` intact — `{"role": "assistant", "content": "", "tool_calls": [{"function": {"name": ..., "arguments": {...}}}]}` — followed by `{"role": "tool", "content": <feed-back text>}`.
   - *Content mode:* the assistant message is re-sent with its content verbatim (prose + ```json fence untouched), followed by the same `{"role": "tool", "content": ...}` shape.
   - The feed-back text is `ToolResult.output` for executed calls (ok or not) and `RepairableError.message` for repair rounds — never anything the loop composed itself.
2. **`status: "error"` transcript field values:** `final_answer` is **`null`** (not empty string); `transcript` holds the steps accumulated before the failure; `iterations` = that length; `tokens` counts only turns that produced a response. The §3 `to_dict()` shape stays exactly seven fields — the failure reason is carried on the in-process `Result.error` attribute (not serialized) and surfaced by the CLI as the exit-4 stderr line.
3. **stderr reason convention:** every non-zero exit prints exactly one line, `local-agent-runner: <reason>`, embedded newlines/whitespace runs collapsed to single spaces so the line count is invariant.
4. **"Malformed call" interpretation:** E1.2's settled boundary classifies *unparseable* content as a `FinalAnswer` (the loop terminates — correct: there is nothing to repair). The loop-visible malformed call is therefore a **parseable call with invalid/missing/uncoercible arguments** (`RepairableError`), and that is what the malformed-then-valid test exercises (content-mode call missing its required argument).
5. **Repair-step `tool_call` recording:** E1.2's `RepairableError` does not carry the attempted name/args, and E1.2 must not be modified in this Epic — so `loop.py` recovers them best-effort from the assistant message (`tool_calls[0]` in native mode; the fenced/bare JSON in content mode), mirroring the §1.2 delivery modes without any validation (classification stays E1.2's). Seam note for a future epic: exposing the attempted call on `RepairableError` would remove this small duplication.
6. **Executed-call transcript args are post-coercion** (what actually ran, e.g. `"2"` recorded as `2`); repair-round args are what the model attempted, verbatim.
7. **`--tools` is required** at the CLI (the §2 invocation and the E1.5 proof both pass one; a tool-less run is not an M1 use case). `--transcript` is optional — without it no run record is written.
8. **argparse flag errors are rerouted to exit 3:** argparse's native exit code for bad usage is 2, which §2 reserves for did-not-converge; the parser subclass converts usage errors into the config-error path (one stderr line, exit 3).
9. **Unwritable `--transcript` path fails at startup** (exit 3, before any model call): existing-directory target, missing parent directory, or unwritable parent are all config errors. A write failure at run end (post-check race) degrades to a best-effort stderr warning without changing the run's exit code.
10. **`per-step ms` is the wall time of the whole round** (chat call + parse + execute), as an integer; `duration_ms` is the wall time of the whole run. `time.monotonic()` for both.
11. **`max_iterations <= 0`** never enters the loop and returns `max_iterations_exceeded` with an empty transcript (§5 pseudocode semantics: `for i in 1..max_iterations`).
12. **`local_agent_runner/__init__.py` untouched:** the Execution Contract forbids modifying E1.1–E1.3 modules, and the public library entry point is deferred beyond M1 — `run` is importable as `local_agent_runner.loop.run`; the CLI is the M1 public surface.

No spec-settled decisions were reopened (iterations = tool rounds; repair rounds are transcript steps; goal-7 CLI flag set only; unknown enabled tool = exit 3; transcripts written for failed runs).
