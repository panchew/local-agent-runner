### Summary

Run the CONTRACT.md §9 atomic proof: a committed fixture task (read a file → edit one
line → run a test that checks the edit), invoked through the E1.4 CLI inside a
container against live `qwen2.5-coder:14b`, converging in **three consecutive runs**
with mechanically-checked clean transcripts committed as milestone artifacts.

### Problem Statement

Every offline test passes, but no model has ever driven this engine. The project's
founding question — can a local model over Ollama HTTP reliably drive a tool-calling
loop to a correct, verifiable result? — stays open until this proof converges
reproducibly. This Epic retires that risk or surfaces exactly where the engine fails
against reality.

### Goals

1. Committed, self-contained proof fixture: `proof/workspace-template/` (source file
   with one unmistakable line to edit + dependency-free `python3 test_app.py`-style
   test), `proof/task.md` (3-step instruction), `proof/tools.json` (three tools scoped
   to exactly what the proof needs)
2. Containerized one-command invocation: `proof/Dockerfile` + `proof/run-proof.sh`
   (build image → for each of 3 runs: reset workspace from template → run CLI with
   `--transcript` → check transcript → stop at first failure); `--network host` for
   Linux host Ollama, endpoint overridable
3. Mechanical cleanliness check: `proof/check_transcript.py` (stdlib) validating §3
   shape, `status: "completed"`, well-formed steps, no unrepaired error in the final
   iteration, edit verified in the workspace — plus offline unit tests for the checker
   itself
4. The proof: three consecutive converging runs; transcripts committed under
   `proof/artifacts/`; failed attempts kept under `proof/artifacts/attempts/` and the
   count of three restarted ("consecutive" is literal)
5. Delivery Notice with per-run `iterations`, `tokens`, `duration_ms`, repair rounds
   observed, and any failed attempts with causes
