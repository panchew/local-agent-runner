## Epic Specification

**Full spec:** `docs/phases/P1__Core_Loop_Proof/P1-M1-E1.1__spec__ollama-http-client.md`
(git-tracked on `milestone/M1`)

### Prerequisite Verification (do this first)

Before relying on the spec, confirm it is **git-tracked on the expected branch** using
`git ls-files --error-unmatch docs/phases/P1__Core_Loop_Proof/P1-M1-E1.1__spec__ollama-http-client.md`

If the path is untracked, STOP and report to the Milestone Chat before proceeding.

E1.1 declares no prerequisite Epics — you start from an empty codebase.

### Summary

Build the typed Ollama HTTP client (`POST /api/chat`, `stream: false`, configurable
endpoint) plus the Python project skeleton it lives in, with typed runtime errors and
fully offline unit tests.

### Problem Statement

There is no code in this repository yet. Every loop iteration in later Epics is one
`/api/chat` round trip; without a client that surfaces `message.content`,
`message.tool_calls`, and `eval_count`, and converts connection/model failures into typed
errors (exit-code-4 semantics), neither the execution loop (E1.4) nor the §9 proof (E1.5)
can exist.

### Goals

1. Typed client: `POST {endpoint}/api/chat` with `stream: false`, carrying `model`,
   `messages`, `tools`, optional `options`; endpoint defaults to `http://localhost:11434`
2. Typed response exposing `message.role` / `message.content` / `message.tool_calls` and
   `eval_count` / `prompt_eval_count` (absent-tolerant), passing both CONTRACT.md §1.2
   delivery modes through **verbatim** — no interpretation (that is E1.2's job)
3. Distinct typed exceptions for connection failure and model-missing, sharing a common
   base (CLI exit code 4 semantics)
4. No `ollama` CLI invocation anywhere in the codebase
5. Bootstrap the project skeleton (`local_agent_runner/` package, `tests/`, minimal
   `pyproject.toml`, pytest) that E1.2–E1.4 will extend

## Acceptance Criteria

- [ ] E1.4 (execution loop) can drive one model turn through this client using only its
      public surface: construct client → `chat(model, messages, tools)` → read `message`
      and `eval_count` from the result
- [ ] A connection failure or missing model is distinguishable by exception type alone,
      sufficient for the CLI to emit exit code 4 with a one-line reason
- [ ] Tests run green in a fresh clone with `pip install` + `pytest` and nothing else (no
      Ollama, no Docker, no GPU)
- [ ] The recorded fixtures faithfully represent both §1.2 delivery modes (native
      `tool_calls` populated; content-embedded JSON with empty native field)

## Technical Constraints

- **Language:** Python
- **HTTP:** `requests` (settled in the spec); never the `ollama` CLI or SDK
- **Endpoint:** configurable, default `http://localhost:11434`; `stream: false` always;
  generous configurable HTTP timeout (model inference is slow on a contended GPU)
- **Testing:** pytest; mocked/recorded responses only — no GPU, no live server
- **Environment:** must run inside a container (CONTRACT.md §10.3); no host-specific paths
