- `local_agent_runner/tool_calls.py` (E1.2, merged)

### Summary

Deliver the three §9 proof tools — `read_file`, `edit_file`, `run_command` — with §4
permission scoping (`allow_paths` globs; `allow_commands`/`deny_commands` patterns;
`timeout`), deny-by-default, and a never-raising `execute_tool` surface whose error
results are deterministic, model-facing repair-loop inputs.

### Problem Statement

The engine can talk to a model (E1.1) and classify what it did (E1.2), but a valid
`ToolCallRequest` has nothing to execute against. Without deterministic,
permission-scoped tools, E1.4 cannot wire the loop and E1.5's proof has nothing to
drive; an unguarded `run_command` would also violate the contract's safety posture.

### Goals

1. Ollama wire-format definitions for the three tools (flat primitive schemas, correct
   `required` lists, model-facing descriptions), filtered by `enabled`
2. Handlers per §4: `read_file(path, start_line?, end_line?)`,
   `edit_file(path, old, new)` (exactly-once replacement), `run_command(command)`
3. `ToolPermissions.from_dict` over the §4 `tools.json` shape; `allow_paths` matched
   against **resolved absolute paths** (traversal-safe); `deny_commands` wins over
   `allow_commands`; **deny by default**; `timeout` enforced
4. `execute_tool(name, arguments, permissions) -> ToolResult(ok, output)` — never
   raises; every expected failure and unexpected exception becomes a deterministic
   error result; non-zero exit codes are **successful** results reporting the code
5. Fully offline unit tests (`tmp_path`, innocuous commands) including the §9 seam:
   read → edit → run-test as three sequential `execute_tool` calls on a temp fixture

## Definition of Done

- [ ] Wire-format definitions exist for the three proof tools, with correct `required`
      lists and flat primitive schemas, filtered by `enabled`
- [ ] `read_file` / `edit_file` enforce `allow_paths` on resolved absolute paths
      (traversal-safe) and deny by default
- [ ] `edit_file` replaces an exactly-once `old` and reports not-found vs ambiguous as
      distinct deterministic errors
- [ ] `run_command` enforces `allow_commands`/`deny_commands` (deny wins, deny by
      default) and `timeout`; reports exit code, stdout, stderr in a fixed, capped
      format; non-zero exit is a successful tool result
- [ ] `execute_tool` never raises: every expected failure and unexpected exception
      becomes a deterministic model-facing error `ToolResult`
- [ ] All unit tests pass via `pytest` offline; no `ollama` CLI invocation anywhere
      (`subprocess` is expected here for `run_command` — the rule is *never invoke
      `ollama`*, not *never subprocess*)
- [ ] Delivery Notice produced and committed
- [ ] All changes committed to `epic/E1.3` branch, delivered for merge to `milestone/M1`
