### Summary

Build `parse_tool_call` — the engine's crux — covering both CONTRACT.md §1.2 delivery
modes, with a closed three-variant result model (tool call / final answer / repairable
error) and JSON-schema argument coercion (§1.3), proven entirely offline against E1.1's
recorded fixtures plus new edge-case fixtures.

### Problem Statement

The loop (E1.4) cannot exist without one well-tested answer to: *given a model response,
what did the model just do?* Valid call, final answer, and repairable mistake are routed
differently by §5. Misclassify, and the loop crashes where it should repair or terminates
where it should act.

### Goals

1. `parse_tool_call(message, tools)` per §5: native `message.tool_calls` first; else
   extract from `message.content` (```json fence or bare
   `{"name": ..., "arguments": {...}}`); else final answer
2. Closed result model the loop routes on by type: `ToolCallRequest` / `FinalAnswer` /
   `RepairableError` (model-facing message + machine-readable kind:
   `unknown_tool` | `invalid_arguments`)
3. `coerce_arguments(arguments, json_schema)`: `"8"` → `8` (§1.3), plus string→number and
   string→boolean; correct types pass through; uncoercible → `invalid_arguments`;
   missing required properties → `invalid_arguments`
4. Validation against enabled tool definitions in Ollama wire format (the same dicts
   E1.1's `chat(tools=...)` accepts and E1.3 will produce)
5. Fully offline unit tests reusing E1.1's fixtures unmodified, plus new edge-case
   fixtures

## Definition of Done

- [ ] `parse_tool_call` returns the native call when `message.tool_calls` is non-empty,
      without touching `content`
- [ ] `parse_tool_call` extracts a content-embedded call from a ```json fence (with or
      without surrounding prose) and from a bare JSON object as the whole stripped
      content, when the native field is empty or absent
- [ ] Nothing-parseable content (including invalid JSON in a fence) yields `FinalAnswer`
- [ ] Unknown tool and invalid/missing/uncoercible arguments yield `RepairableError`
      with a model-facing message and machine-readable kind
- [ ] `coerce_arguments` fixes string-encoded integers, numbers, and booleans against
      the schema; passes correct types through; reports uncoercible values as
      `invalid_arguments`
- [ ] All unit tests pass via `pytest` offline; E1.1's three chat fixtures reused,
      unmodified
- [ ] No `ollama` CLI invocation introduced anywhere
- [ ] Delivery Notice produced and committed
- [ ] All changes committed to `epic/E1.2` branch, delivered for merge to `milestone/M1`
