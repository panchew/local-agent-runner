## Decisions settled during execution (recorded per spec)

1. **Checker error-detection rule** (spec §3 left it to this Epic): a step's
   `tool_result` is an *error result* iff it starts with one of the engine's
   deterministic error forms — `unknown tool '` (E1.2 repair / E1.3
   unknown-tool), `invalid arguments for tool '` (E1.2 coercion repair),
   `read_file: ` or `run_command: ` (every E1.3 error template for those
   tools carries the `{tool}: ` prefix and no successful result does:
   `read_file` success is raw file content, `run_command` success starts
   with `exit_code: `), and `edit_file: ` except the single success form
   `edit_file: replaced `. A `run_command` result with a non-zero exit code
   is **not** an error result (§4: a failing test is information). Unit
   tests pin the rule against the verbatim E1.3/E1.2 message forms.
2. **Genuineness checks beyond the milestone wording** (guarding the
   no-hollow-proof constraint mechanically): the transcript must contain a
   non-error `read_file` step, a successful `edit_file` step *after* the
   first successful read, and a `run_command` step reporting `exit_code: 0`
   *after* that edit; plus strict §3 shape (exactly the seven keys; exactly
   the four step keys) and `eval_count` a positive integer per step.
3. **Task wording** (final on the first attempt — no tuning needed): the
   task states the *intent* of the edit ("edit `app.py` so that
   `get_value()` returns 42"), not the patch — the model located
   `VALUE = 41` itself by reading the file. The answer is not embedded, the
   edit is not pre-applied, the workspace test is unweakened.
4. **Workspace mount, not bake:** the container bakes `task.md`/`tools.json`
   but mounts the run workspace (`proof/run-workspace`, gitignored) and
   `proof/artifacts/` from the host, so the checker can verify workspace
   state directly and transcripts land on the host; `docker run --user
   "$(id -u):$(id -g)"` keeps artifacts user-owned.
5. **Runner failure handling:** stop at first failure, move the failed
   transcript to `proof/artifacts/attempts/attempt-<timestamp>-run<n>.json`,
   exit 1 with an explicit "the count of three restarts" message.
6. **Offline rehearsal before GPU time:** the full pipeline (image, container,
   CLI, real tool execution, checker, runner verdict and failure path) was
   rehearsed against a scripted stand-in Ollama server speaking qwen's
   content-embedded delivery mode — the live runs were the first time the
   harness met the real model, and it converged immediately.

No spec-settled decisions were reopened (three-consecutive definition,
dependency-free test, `--network host`, template reset per run, failed
attempts kept, engine read-only).
