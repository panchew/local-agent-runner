### Summary

Assemble the engine: the CONTRACT.md §5 execution loop wiring E1.1–E1.3 together with
repair-don't-crash feedback and deterministic termination, the §3 Result/transcript with
token accounting, and the §2 CLI with exit codes 0/2/3/4 — proven offline with a
scripted fake client.

### Problem Statement

The engine's parts exist but there is no engine: nothing maintains message history,
routes parse outcomes, feeds errors back, enforces the ceiling, records the transcript,
or maps outcomes to exit codes. Until E1.4 lands, the §9 proof cannot be attempted.

### Goals

1. The §5 loop exactly: `[system?, context?, user(task)]` seeding; at most
   `max_iterations` turns; no-tool-call turn → final answer; tool results and every
   repairable condition (malformed call, unknown tool, invalid arguments, denied
   permission, handler failure) fed back as tool results
2. Deterministic termination: `completed` / `max_iterations_exceeded` (default 10) /
   `error` (client failure, transcript preserved)
3. §3 Result: `status`, `final_answer`, transcript steps
   (`tool_call:{name,args}`, `tool_result`, `ms`, `eval_count`), `iterations`, total
   `tokens` (every turn counted, final turn included), `model`, `duration_ms` — JSON
   to `--transcript`
4. §2 CLI: `--model` (default `qwen2.5-coder:14b`), `--task`/`--task-text`, `--tools`,
   `--max-iterations`, `--endpoint`, `--transcript`; exit codes 0/2/3/4 with a one-line
   stderr reason; final answer on stdout; console script + `python -m`
5. Fully offline tests via an injectable fake client (`run(client=...)`)

## Definition of Done

- [ ] The loop routes all three parse outcomes and both delivery modes; repairs on
      malformed call, unknown tool, invalid arguments, denied permission, and handler
      failure; and always halts (final answer or ceiling)
- [ ] `Result.to_dict()` matches the §3 shape exactly: `status`, `final_answer`,
      `transcript` steps with `tool_call:{name,args}` / `tool_result` / `ms` /
      `eval_count`, `iterations`, `tokens`, `model`, `duration_ms`
- [ ] `tokens` includes every turn's `eval_count` (final turn included; `None` as 0)
- [ ] The CLI exposes exactly the goal-4 flag set with §2 defaults, prints the final
      answer to stdout on success, and writes the transcript JSON for every run that
      reaches the loop (including `error` and `max_iterations_exceeded` runs)
- [ ] Exit codes 0/2/3/4 per the spec mapping, each non-zero exit with a one-line
      stderr reason
- [ ] `local-agent-runner` (console script) and `python -m local_agent_runner` both
      invoke the CLI
- [ ] All unit tests pass via `pytest` offline; no `ollama` CLI invocation anywhere
- [ ] Delivery Notice produced and committed
- [ ] All changes committed to `epic/E1.4` branch, delivered for merge to `milestone/M1`
