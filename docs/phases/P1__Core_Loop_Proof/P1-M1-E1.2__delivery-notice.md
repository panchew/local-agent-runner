## Decisions settled during execution (per spec Execution Notes)

1. **`coerce_arguments` raises `ArgumentCoercionError`** (a `ValueError`) for missing-required and uncoercible values; `parse_tool_call` catches it and returns `RepairableError(invalid_arguments)`. This keeps the function independently callable while the parse surface stays a closed three-variant set.
2. **Valid JSON that is not call-shaped is a `FinalAnswer`.** The content forms of §5 require a dict with `"name"` (string) and `"arguments"` (object); anything else parseable-but-not-a-call (e.g. `{"answer": 42}`, a list, a non-dict `arguments`) is the answer, not an error — only *parseable-as-a-call but wrong* becomes repairable.
3. **`bool` is rejected for `integer`/`number` properties** (Python `bool` subclasses `int`; `True` for `start_line` is a model mistake, not a valid integer) → `invalid_arguments`.
4. **Wrong-type values for `string` properties → `invalid_arguments`.** String properties are never coerced (per spec), so a non-string there is reported, not converted.
5. **Untyped or non-primitive property schemas pass through untouched** — flat primitive coercion scope only (spec-settled), the handler decides.
6. **A native call with a missing or non-dict `arguments` field is treated as `{}`**, letting required-property validation produce the repair message rather than crashing.
7. **First ```json fence wins** when content holds several; consistent with first-only native calls.
8. **No robustness beyond the two specified content forms was added** (no plain ``` fence, no best-effort bare-object-in-prose extraction) — nothing extra to record as additive.
9. **`coerce_arguments` returns a new dict** and never mutates the caller's arguments (`test_original_arguments_dict_is_not_mutated`).

No spec-settled decisions were reopened (first-only native calls; invalid-JSON fence → final answer; closed three-variant result model; flat primitive coercion only).
