## Decisions settled during execution (per spec Execution Notes)

1. **Absent token fields default to `None`, not `0`.** Absence on the wire is preserved (absent ≠ measured zero); `ChatResponse.raw` remains the unmodified source of truth. Consumers summing tokens (E1.4 transcript) should treat `None` as `0` (`resp.eval_count or 0`).
2. **HTTP errors that are not model-missing raise the base `OllamaClientError`.** Model-missing is detected from the error body (`"model" + "not found"` / `"no such model"`, case-insensitive) on any ≥400 status; other HTTP failures still map to exit-code-4 semantics via the shared base.
3. **`chat(...)` accepts both `ChatMessage` objects and plain dicts in `messages`** — the loop (E1.4) can append raw response messages without conversion.
4. **`tools` / `options` are omitted from the request body when not provided** (rather than sent as `null`).
5. **Fixture fidelity choices:** the content-embedded fixture carries `"tool_calls": []` (the observed "empty native field" of §1.2); the final-answer fixture omits the key entirely — the client tolerates both (`[]` and `None` respectively). The native fixture deliberately keeps llama3.1's string-typed integer argument (`"start_line": "8"`, §1.3) so E1.2 can reuse it for coercion tests.
6. **Endpoint trailing slash is normalized** (`rstrip("/")`) so `http://host:port/` and `http://host:port` behave identically.

No spec-settled decisions were reopened (`requests` as HTTP library; passthrough client; E1.1 owns the skeleton).
