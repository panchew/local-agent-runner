## Decisions settled during execution (per spec Execution Notes)

1. **`run_command` result block format** (E1.4's transcript and E1.5's proof show this verbatim):

   ```
   exit_code: <int>
   stdout:
   <stdout, capped>
   stderr:
   <stderr, capped>
   ```

2. **Output cap:** `OUTPUT_CAP = 4000` characters **per stream** (stdout and stderr capped independently); overflow is cut at the cap and suffixed with the marker `\n[truncated: stream exceeded 4000 characters]` (§6 token discipline).
3. **Denial messages state what permitted looks like:** the path-denied message lists the `allow_paths` globs; the command-denied message lists the `allow_commands` patterns (noting deny wins). Empty knobs render as `(none - no paths are permitted)` / `(none - no commands are permitted)`. All messages are module-level templates — determinism by construction.
4. **Path matching:** `fnmatch.fnmatchcase` (not `fnmatch.fnmatch`) against `str(Path(p).resolve())`, for byte-identical case-sensitive behavior across platforms; `resolve()` eliminates symlinks and `..` before matching, so traversal cannot escape.
5. **Permission check precedes existence check** in both file tools: a denied path yields the denial message whether or not the file exists (no existence oracle outside the allowed globs).
6. **`read_file` range semantics:** `start_line`/`end_line` are 1-based inclusive; defaults are 1 and EOF. Errors when `start_line < 1`, `start_line >` line count, or `end_line < start_line`; an `end_line` past EOF clamps to EOF (a friendly over-ask is not a model mistake worth a repair round-trip).
7. **Command patterns match the whole command string as given** — no trimming or normalization; `fnmatchcase` semantics per the spec.
8. **§4 tools not in this Epic (`write_file`, `list_dir`, `git`) are unknown at execution time** → the deterministic unknown-tool error listing the three available tools; `tool_definitions` silently ignores unknown names in `enabled` (rejecting them at config time is E1.4's call).
9. **Non-string values for required string arguments** produce a deterministic bad-argument error rather than an exception — `execute_tool` is a public surface and must hold its never-raises contract even when called without E1.2's coercion in front.
10. **File tools never modify the file on an error path** (denied, missing, not-found, ambiguous) — asserted on disk in tests.
11. **Directory (or other non-regular-file) paths** get a distinct deterministic "not a regular file" error.

No spec-settled decisions were reopened (`shell=True`; deny-by-default; non-zero exit = successful result; exactly-once `edit_file`; never-raising `execute_tool`).
