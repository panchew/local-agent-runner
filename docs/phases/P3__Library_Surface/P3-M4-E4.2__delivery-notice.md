## Verification summary (external-service tool)

The full per-check claims and evidence are in
`proof/artifacts/custom-tools/ticket-service/verification-results.md`.

- **Security (11):**
  - Secrets never reach the model, even when the service echoes them (0 eight-character key
    fragments in anything model-facing).
  - The model can't choose the host (attacker server: 0 hits).
  - Path-traversal and injection ids are rejected locally (9 payloads, 0 requests, `/admin`
    honeypot 0 hits).
  - Redirects aren't followed, and insecure base URLs are refused.
  - Injected instructions in third-party data are blocked by the permission layer (no command
    executed, in 2 permission configurations).
  - Wrong credentials give a clean 401.
  - A hang is bounded (about 0.9 s against a 1.9 s bound).
  - Oversized replies are rejected, whether or not they declare their length.
- **Idempotency (10):** each case below leaves exactly 1 ticket on the service.
  - The model repeats the same call.
  - The connection drops after the commit.
  - A timeout after the commit.
  - 503s before the commit.
  - Retries are bounded, then the model retries.
  - The model retries after an ambiguous failure.

  Separately:
  - Different arguments aren't merged.
  - The key scope is per run, and resuming a run with the same `run_scope` replays rather than
    duplicating.
  - Reads don't change state.
  - The fake service's 409 contract holds.
- **Integrity (8):**
  - Requests are HMAC-signed, and a tampered request gets 401.
  - Tampered responses are rejected by the signature check specifically, on both create and
    get.
  - Unsigned responses are rejected.
  - Validly signed but wrong tickets are rejected.
  - Unicode, quotes and 200-character titles round-trip byte for byte.
  - The service's end state matches the transcript exactly.

## Findings during execution

1. **A secret-leak bug in the first draft of the reference tool, caught in review.** The tool
   truncated a service error to 200 characters *before* redacting secrets. A key that
   straddled the cut would have left a fragment that whole-string redaction no longer matches.
   It's fixed (redact, then truncate). It's pinned by SEC-01, because the fake service places
   the key at offset 185 on purpose, and by mutation M02.
2. **The first mutation run found 3 survivors. All were resolved, none by weakening a check.**
   - *M06 (streaming size cap disabled):* SEC-09 only sent responses that declared their
     `Content-Length`, so the up-front check masked the streaming cap. I added the
     `HUGE_UNDECLARED` fault and a parametrized case. **Test gap, fixed.**
   - *M11 (response signature check disabled):* INT-02 tampered only with `create`, where the
     echo check also catches the change, and it asserted the generic "integrity check failed".
     I added a `get` variant, where the signature is the only guard, and asserted the specific
     reason. **Test gap, fixed.**
   - *M07 (fresh key per call):* my *expectation* was wrong. A per-call key still deduplicates
     transport retries, so IDEM-02/03 rightly passed. I corrected the expectation to IDEM-01/06,
     which failed, and added M07b (a fresh key per retry), which IDEM-02/03 do catch.
   - I dropped one contrived mutation (it only "failed" through an unreachable assertion)
     instead of keeping it for the count.
3. **Result tracking marked every run dirty.** The report's own output files counted as
   uncommitted changes. The report directory is now excluded from the `git_dirty` check, and
   this was verified in the dry-run delivery.

## Decisions settled during execution

1. **Library only, CLI unchanged.** This follows CONTRACT §4: the CLI path never runs
   caller-supplied code.
2. **Registration is enablement, and `ToolPermissions` doesn't apply to custom tools.** A
   handler runs with the caller's privileges. This is documented in CONTRACT §4.1, README and
   the module docstring. The reference tool shows the expected self-scoping: a pinned host,
   validated arguments and credentials kept out of the model's reach.
3. **Name collisions are rejected before the first model call** with `ValueError`. That
   includes shadowing *any* built-in, enabled or not, so routing is never ambiguous. It's the
   same principle as the CLI's exit-3 config strictness: a caller mistake, not a model mistake.
4. **There's no global registry.** Only the tools passed to `run()` exist for that run, and a
   test asserts this.
5. **Schema inference covers flat primitives only**, matching the §1.3 coercion scope. An
   explicit `parameters=` is the escape hatch (the reference tool uses it for `enum` and
   per-argument descriptions). Unsupported signatures fail when the function is decorated.
6. **Handler output isn't capped by the runner.** It's left to the tool, and documented as
   such in §4.1. See follow-up 3.
7. **Idempotency keys are scoped per tool set, meaning per run.** Separate runs creating "the
   same" ticket create two tickets. Passing the same `run_scope` resumes a run safely. This is
   deliberate and tested (IDEM-08).
8. **`custom_tools.py` imports two private names from `tools.py`** (`_MSG_UNEXPECTED`,
   `_TOOL_ORDER`). This reuses the deterministic error template and the single source of
   built-in names, and leaves `tools.py` unmodified.
9. **Result tracking is opt-in.** A plain `pytest` writes nothing. Evidence uses pytest's
   built-in `record_property`, so it also appears in `--junitxml` output.

## Known limitations and follow-ups (proposed carry-forward)

1. **Live-model proof (DoD 12) is pending on the host.** Until it runs, model behavior with
   the real `qwen2.5-coder:14b` is unverified. Everything else was checked with scripted
   models and stub servers.
2. **The Python 3.9 floor has been checked statically but not executed** (`requires-python >=
   3.9`; only 3.12 was available). All 13 new or changed Python files parse under the 3.9
   grammar. Every `X | None` or `list[...]` annotation is postponed
   (`from __future__ import annotations`), and no post-3.9 standard-library API is used.
   Remaining caveat: on 3.9, `@custom_tool` raises `TypeError` when the function is decorated
   if a *user's* function uses `X | None` in **any** annotation, including the return type.
   That's because `typing.get_type_hints` evaluates all of them. The workaround is to pass
   `parameters=` explicitly, which skips hint inference.
3. **There's no runner-level output cap for custom tools** (§6). A candidate for CF-4
   hardening: apply `OUTPUT_CAP` to custom tool output, or make it configurable.
4. **The model sees the handler's qualified name in argument errors**, for example
   `make_ticket_tools.<locals>.create_ticket()`. This is cosmetic.
5. **Limits of the external-service verification:**
   - The service is a fake, and it assumes the real API honors `Idempotency-Key`.
   - HTTPS itself isn't exercised. Only the refusal of plain `http://` to remote hosts is.
   - Response HMACs are a fake-service convention; most real APIs rely on TLS.
6. **E4.1 housekeeping, not this Epic's scope.** The E4.1 spec is still `status:
   in-execution`, with no Delivery Notice, although its exports are present and tested. Flagged
   for HQ.
7. **Version.** Not bumped. README marks this as *Unreleased, on top of v2.0.0*. The version is
   for the P3 phase closure to decide.
