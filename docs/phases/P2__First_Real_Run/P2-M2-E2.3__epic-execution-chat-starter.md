### Summary

Add a strictly bounded (**at most one** extra model call, ever) repair nudge to the §5
execution loop: when the terminating turn is a junk blob (empty content, or a parsed
`{"name": ...}`-shaped object), or when `max_iterations` is exhausted without a
`FinalAnswer`, issue one tools-disabled corrective call asking directly for a plain-text
answer. `final_answer` may improve; `status` never changes.

### Problem Statement

The v1.0.0 audit found the terminating turn systematically unreliable on Q&A-shaped
tasks: sometimes a leftover tool-call-shaped blob leaks through as the "answer";
sometimes the model burns the whole iteration budget on tool-calling and never answers
at all. Neither is a correctness bug (the loop terminates deterministically either way)
— it's a usability gap this Epic closes without touching the loop's actual convergence
signal.

### Goals

1. Detect a junk terminating turn: empty/whitespace content, or content that parses as
   a JSON object containing `"name"`
2. Detect ceiling exhaustion: `max_iterations` tool-rounds consumed with no
   `FinalAnswer` ever produced
3. On either trigger, exactly one corrective `client.chat(..., tools=None, ...)` call
   with a nudge message; whatever comes back becomes `final_answer`, even if it is
   itself unusable — no second attempt, ever
4. `status` is never changed by the nudge: `completed` stays `completed`;
   `max_iterations_exceeded` stays `max_iterations_exceeded`
5. Corrective-call failure (`OllamaClientError`) falls back to the pre-nudge result
   exactly — no new exception path
6. The corrective call's `eval_count` is added to `Result.tokens`; `transcript`/
   `iterations` are unaffected (the corrective call is not a tool round)
7. Offline unit tests against a scripted `FakeClient` for both trigger conditions, the
   no-second-nudge bound, and the fallback-on-failure path

## Definition of Done

- [ ] A junk terminating turn (empty content, or a parsed `{"name": ...}`-shaped object)
      triggers exactly one corrective, tools-disabled call; `final_answer` is replaced
      with its content; `status` remains `completed`
- [ ] Ceiling exhaustion (no `FinalAnswer` within `max_iterations`) triggers exactly one
      corrective, tools-disabled call; `final_answer` (previously `None`) is populated
      with its content; `status` remains `max_iterations_exceeded`
- [ ] A real prose final answer never triggers the nudge (no extra `chat()` call)
- [ ] The nudge never fires more than once per run, in either trigger branch, even if
      its own response is itself unusable
- [ ] A corrective-call failure (`OllamaClientError`) falls back to the pre-nudge result
      exactly — no new exception path, no `status` change
- [ ] The corrective call's `eval_count` is included in `Result.tokens`; `transcript`
      and `iterations` are unaffected by the nudge in both branches
- [ ] `run(...)`'s public signature is unchanged
- [ ] All unit tests pass via `pytest`, fully offline
- [ ] Delivery Notice produced and committed
- [ ] All changes committed to `epic/E2.3` branch, delivered for merge to `milestone/M2`
