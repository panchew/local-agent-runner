## Epic Specification

**Full spec:**
`docs/phases/P2__First_Real_Run/P2-M2-E2.2__spec__git-tool-and-subcommand-scoping.md`
(git-tracked on `milestone/M2`)

### Prerequisite Verification (do this first)

Before relying on the spec, confirm it — and this Epic's prerequisite artifacts — are
**git-tracked on the expected branch** using `git ls-files --error-unmatch <path>` run on
`milestone/M2`, not a disk-existence check. Disk presence is not proof of commit. If any
path is untracked, STOP and report to the Milestone Chat before proceeding.

Verify on `milestone/M2`:
- `docs/phases/P2__First_Real_Run/P2-M2-E2.2__spec__git-tool-and-subcommand-scoping.md`
- `local_agent_runner/tools.py` (E2.1, merged — `ToolPermissions`, `ToolResult`,
  `_require_string`, `_cap_stream`, `OUTPUT_CAP`, `_TOOL_ORDER`, `execute_tool`)

### Summary

Add `git(args)` to the tool library: parses `args` with `shlex.split` and runs `git` as
a real subprocess with `shell=False` (no shell-injection surface at all). Gate execution
with a new `allow_subcommands` permission knob on `ToolPermissions` that exact-matches
only the first parsed token, deny by default. Report results in the same fixed, capped
format `run_command` already uses; non-zero exit is a successful result.

### Problem Statement

A real Epic can edit and create files (E2.1) but still cannot commit its work — `git` is
the last built-in CONTRACT.md §4 lists and doesn't exist yet. An unscoped or
shell-interpolated `git` could run destructive or network-reaching subcommands;
`allow_subcommands` is the guardrail.

### Goals

1. `git(args)`: parse into argv tokens (`shlex.split`), run as `subprocess.run(["git",
   *tokens], shell=False, ...)` — never a shell
2. `ToolPermissions.allow_subcommands`: exact-match list, deny by default; enforced on
   the first parsed token only (no global flags before the subcommand)
3. Deterministic errors (not crashes) for: denied subcommand, no subcommand provided,
   unparsable `args`, timeout
4. Same fixed/capped output format as `run_command`; non-zero exit is a **successful**
   result
5. Offline unit tests against real local git repos (`git init` in `tmp_path`, no
   network, no remote)

## Definition of Done

- [ ] `git(args)` parses arguments without a shell and runs `git` as a real subprocess
- [ ] `allow_subcommands` enforces exact-match, deny-by-default permission on the first
      parsed token only; denied subcommands never reach `subprocess.run`
- [ ] Parse failures and "no subcommand provided" each produce a deterministic error,
      not an exception
- [ ] Timeouts produce a deterministic error using the existing `timeout` knob
- [ ] `git`'s success output uses the same fixed, capped format as `run_command`; a
      non-zero exit code is a successful tool result
- [ ] All unit tests pass via `pytest`, fully offline (real local git repos in
      `tmp_path`; no network, no remote)
- [ ] Delivery Notice produced and committed
- [ ] All changes committed to `epic/E2.2` branch, delivered for merge to `milestone/M2`

## Acceptance Criteria

- [ ] A permitted subcommand (e.g. `commit`) actually runs and its effect is observable
      on disk (a real commit in a fixture repo)
- [ ] A denied subcommand returns a deterministic tool-error message and demonstrably
      never invokes `git` (repair-loop input, not a crash)
- [ ] `git diff --exit-code` (or an equivalent non-zero-exit case) returns `ok=True`
      with the exit code visible in the output
- [ ] Tests run green in a fresh clone with `pip install -e ".[dev]"` + `pytest` and
      nothing else — no network access required

## Technical Constraints

- **Language:** Python; changes confined to `local_agent_runner/tools.py`,
  `tests/test_tools.py`
- **Command execution:** `subprocess.run(["git", *shlex.split(args)], shell=False,
  timeout=permissions.timeout)` — never `shell=True` for `git`
- **Argument parsing:** `shlex.split` (POSIX mode); a `ValueError` is a deterministic
  error, not a crash
- **Testing:** pytest, fully offline; `tmp_path` fixtures with `git init` +
  locally-scoped `user.name`/`user.email`; no network
- **Environment:** must run inside a container (CONTRACT.md §10.3); `git` must be on
  `PATH`
