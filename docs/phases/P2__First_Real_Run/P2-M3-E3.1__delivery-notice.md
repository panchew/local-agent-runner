## Decisions settled during execution (per spec Execution Notes)

1. **Build order followed the spec's Execution Notes verbatim:** `--context` flag + `_load_context` in `cli.py` → the two mechanical unit cases in `tests/test_cli.py` → the adapter-shape fixture assets → the five fixture tests in the new module, sharing one set of fixture inputs throughout.
2. **The adapter-contract module defines its own message-recording `FakeClient`** rather than importing `tests/test_loop.py`'s — the spec explicitly permits either ("either import/reuse it or add an equivalent to the new module"). `tests/` has no `__init__.py`, so cross-module imports between test files rely on pytest's import-mode path insertion rather than package structure; a self-contained equivalent avoids that fragility while matching the same shape (records `model`/`messages`/`tools`/`options` per call).
3. **`pip`/`venv` were unavailable in this execution sandbox**, so the DoD's "fresh clone with `pip install -e '.[dev]'`" step could not be literally exercised. `pytest` was instead run directly against the working tree, which is sufficient to prove all new/changed test logic; the console-script entry-point test (`tests/test_cli.py::TestEntryPoints::test_console_script`) was confirmed to skip identically on `milestone/M3` *before* this Epic's changes (`git stash` + targeted run), establishing the skip is pre-existing and not a regression introduced here.
4. **The exit-2 fixture's `EndlessToolCaller` calls `read_file` against `/repo/README.md`**, a path that does not exist in the test sandbox — this is intentional: the coding-set `tools.json` fixture's `allow_paths` is `["/repo/**"]` per CONTRACT.md §4's own example shape (a repo-scoped glob, not a `tmp_path`-scoped one), so the call is permission-*permitted* but file-*missing*, producing an ordinary repair round each iteration. This keeps the fixture's `tools.json` identical across all five tests (the "one consistent invocation pattern" requirement) rather than swapping in a test-host-specific glob for the exit-2 case alone.
5. **No spec-settled decisions were reopened:** `--context` remains a single file-based flag with no `--context-text` companion; no test in the new module asserts on `final_answer`'s content; `--system` was not exposed; `loop.py`, the SN-3 repair nudge, and the tool/permission model were not touched; no exit code, `Result`/§3 field name, or transcript shape changed.
