## Decisions settled during execution (per spec Execution Notes)

1. **Build order followed the spec's Execution Notes verbatim:** `_is_unusable_final_answer` → nudge-text constants → `_request_plain_answer` helper → wired into the junk-terminating-turn branch → wired into the ceiling-exhaustion branch → tests throughout.
2. **`_is_unusable_final_answer` reuses the existing `_JSON_FENCE` regex** already defined in `loop.py` (used by `_attempted_call`) — no second regex added, per the spec's explicit instruction.
3. **The ceiling-exhaustion branch does not re-append `response.message`** before the corrective call. The spec's Execution Notes describe reusing "the `messages.append(response.message)` pattern already established in the tool-round branch" — and that pattern *already* runs on every completed tool round, including the loop's final iteration (the only way to reach ceiling exhaustion is for every iteration, including the last, to take the tool-round branch, which already appends the assistant turn and its tool feedback). Re-appending there would duplicate the assistant message the model already produced. The junk-terminating-turn branch is different: that code path returns *before* the existing tool-round `messages.append(response.message)` ever runs, so an explicit append was added there — matching the spec's explicit instruction for that branch and mirroring the pattern's *effect* (the model's own prior turn is in context) rather than literally re-executing the same line in a place where it would double up.
4. **Two pre-existing tests outside the stated `local_agent_runner/loop.py` / `tests/test_loop.py` constraint were updated, not added to:** `tests/test_loop.py::TestTermination::test_ceiling_halts_endless_tool_caller`/`test_default_ceiling_is_ten` and `tests/test_cli.py::TestDidNotConverge::test_ceiling_exit_2_transcript_written` all use an `EndlessToolCaller` fake that ignores `tools=None` and always returns a tool-call-shaped response. Before this Epic, that fake never emitted a `FinalAnswer`, so ceiling exhaustion was the only outcome; after this Epic, ceiling exhaustion now triggers exactly one corrective call — which `EndlessToolCaller` also answers (again tool-call-shaped, content `""`), consuming one more call and populating `final_answer` with `""` instead of leaving it `None`. This is the nudge behaving exactly as specified (one attempt, no retry, raw content accepted as-is even when unusable) — the three assertions (`client.calls`, `result.final_answer`/`result.tokens` in `test_loop.py`) were updated to match the new, intended call count and result; no `cli.py` source file was touched, and the CLI's exit-code mapping is unaffected (`test_cli.py`'s `rc == EXIT_DID_NOT_CONVERGE` assertion is untouched). This mirrors E2.2's precedent of updating a pre-existing test whose premise became false without touching out-of-scope source.
5. **No spec-settled decisions were reopened:** `status` is never changed by the nudge in either branch; at most one corrective call, full stop, even when the corrective response is itself unusable-shaped; the corrective round is not a transcript step; a corrective-call failure is silent (falls back to the pre-nudge result), never a new `status == "error"` path.
