# Epic E2.1 — write_file & list_dir Tools + Test Suite Housekeeping

## Context

P1 closed at `v1.0.0` with three read-mostly proof tools (`read_file`, `edit_file`,
`run_command`) and the `allow_paths`/`allow_commands`/`deny_commands`/`timeout` permission
knobs, all living in `local_agent_runner/tools.py` behind the never-raising
`execute_tool(name, arguments, permissions) -> ToolResult` surface (E1.3). A real Epic
needs to create new files and inspect directories — neither is possible yet.

This Epic extends `tools.py` with `write_file` and `list_dir`, scoped by the same
`allow_paths` mechanism `read_file`/`edit_file` already use (`ToolPermissions.path_permitted`,
resolved-absolute-path matching, deny by default, traversal-safe). It also lands the
pytest deprecation-warning fix carried forward from P1, per the Phase spec's explicit
direction that it land in P2's first epic.

---

## Problem Statement

Without `write_file`, a real Epic's Coding Agent cannot create the files its work
requires; without `list_dir`, it cannot discover what already exists in a directory
before acting on it. Both gaps block M3's first real run. Separately,
`tests/test_check_transcript.py::test_step` is a step-builder helper that pytest
collects as a test (its name matches pytest's `test_*` discovery pattern) and which
returns a dict instead of `None`, producing a `PytestReturnNotNoneWarning` on every test
run. The Phase spec requires this fixed in P2's first epic.

---

## Goals

By the end of this Epic, the system must:

1. Provide `write_file(path, content)`: creates a new file or overwrites an existing one,
   scoped by `allow_paths`, using the same resolved-absolute-path permission check as
   `read_file`/`edit_file`
2. Provide `list_dir(path)`: lists the immediate contents of a directory, scoped by
   `allow_paths`, using the same permission check
3. Keep `allow_paths` enforcement semantics **identical** across all four file tools
   (`read_file`, `edit_file`, `write_file`, `list_dir`) — same resolver, same glob
   matching, same deny-by-default rule
4. Eliminate the pytest deprecation warning from `tests/test_check_transcript.py` without
   changing the transcript-checker test suite's behavior or coverage
5. Cover both new tools with offline unit tests (temp dirs, no GPU, no Ollama, no network)

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Ship the `git` tool or `allow_subcommands` enforcement (E2.2)
- Implement the SN-3 final-answer repair nudge (E2.3)
- Change `run_command`'s permission model or behavior — it is already complete from P1
- Support recursive/deep directory listing — `list_dir` lists one directory's immediate
  entries only
- Support deleting, moving, or renaming files — only creating/overwriting (`write_file`)
  and listing (`list_dir`)
- Build the governance adapter, the library entry point, or any UI (out of scope for all
  of M2 per the Milestone spec)

## Scope of Work

### 1. `write_file` tool

Add to `local_agent_runner/tools.py`:

- Wire-format definition (flat primitive schema): `path` (string, required), `content`
  (string, required)
- Handler `_write_file(arguments, permissions) -> ToolResult`:
  - Resolve `path` the same way `_checked_file` does (`Path(path).resolve()`) and check
    `permissions.path_permitted(resolved)` — deny by default, same message template
    shape as the existing `_MSG_PATH_DENIED` (tool name `write_file`)
  - **Unlike `read_file`/`edit_file`, the target file need not already exist.** If the
    resolved path's parent directory does not exist, create it (and any missing
    ancestors) before writing — a real Epic will `write_file` into new subdirectories
    (`mkdir(parents=True, exist_ok=True)` semantics)
  - If the resolved path already exists and is a directory (not a regular file), return
    a deterministic error — do not overwrite a directory
  - Otherwise write `content` to the resolved path (creating or truncating), and return
    a success result: `f"write_file: wrote {len(content)} characters to '{resolved}'."`
  - `content` must be a string (reuse `_require_string`); a non-string `content` is a
    deterministic argument error, matching the existing `_MSG_BAD_ARGUMENT` shape

### 2. `list_dir` tool

Add to `local_agent_runner/tools.py`:

- Wire-format definition: `path` (string, required)
- Handler `_list_dir(arguments, permissions) -> ToolResult`:
  - Resolve `path` and check `permissions.path_permitted(resolved)` — same deny-by-default
    rule and message shape (tool name `list_dir`)
  - Resolved path must exist and must be a directory; missing path and "exists but is a
    file" are distinct deterministic errors (mirror `_MSG_FILE_MISSING`/`_MSG_NOT_A_FILE`
    wording, adapted for a directory target)
  - List the directory's **immediate** entries only (no recursion), sorted
    alphabetically; each subdirectory entry is suffixed with `/` to distinguish it from a
    file entry
  - An empty directory returns a fixed, deterministic message (e.g.
    `"list_dir: '{path}' is empty."`) rather than an empty string
  - Cap the total listing at `OUTPUT_CAP` characters using the existing truncation
    marker convention (§6 token discipline) — reuse `_cap_stream` rather than a second
    cap implementation

### 3. Tool registry

- Add both tools to `_DEFINITIONS` and to `_HANDLERS`
- Update `_TOOL_ORDER` to `["read_file", "write_file", "edit_file", "list_dir",
  "run_command"]` (CONTRACT.md §4 table order; `git` is added by E2.2). This governs
  `tool_definitions()`'s canonical output order and the tool list named in
  `_MSG_UNKNOWN_TOOL`

### 4. Test suite housekeeping

`tests/test_check_transcript.py` defines a step-builder helper named `test_step(result=
TEST_PASS_RESULT)` that returns a `dict` (a `run_command` transcript step). Because its
name matches pytest's default `test_*` collection pattern, pytest collects it as a test
function and warns (`PytestReturnNotNoneWarning`) because it returns a non-`None` value
instead of asserting.

**Fix:** rename the helper from `test_step` to `run_step` throughout
`tests/test_check_transcript.py` (the definition and all ~20 call sites). This removes
it from pytest's test collection entirely — the correct fix, since the function is a
value-returning builder consumed by other tests, not an assertion itself. **Do not**
change its `return` to an `assert`: every other test in the file calls
`run_step()`/`run_step(TEST_FAIL_RESULT)` for its return value, and converting it to
assert semantics would break every call site. (This resolves the letter of the Milestone
spec's "`test_step`, `return` instead of `assert`" note — that phrase names the pytest
warning's own suggested remedy for return-value tests in general, not a literal
instruction to add an `assert` to this particular builder.) Do not touch anything else
in the file — `check_transcript.py`'s behavior and every other test's assertions are out
of scope.

### 5. Unit tests

Extend `tests/test_tools.py` (offline, `tmp_path`, no GPU/Ollama/network):

- `write_file`: creates a new file with the given content (verified on disk); overwrites
  an existing file's content; creates missing parent directories; denied path (outside
  `allow_paths`); target path exists and is a directory → deterministic error;
  non-string `content` → deterministic argument error
- `list_dir`: lists files and subdirectories in a fixture directory, sorted, directories
  suffixed with `/`; empty directory → the fixed empty-directory message; denied path;
  missing directory; path exists but is a file, not a directory; output cap enforced on
  a directory with many entries
- Cross-tool consistency: a single parametrized test asserting all four file tools
  (`read_file`, `edit_file`, `write_file`, `list_dir`) deny the same out-of-`allow_paths`
  resolved path and the same `..`-traversal path, using the same `ToolPermissions`
  instance
- `tool_definitions`/`execute_tool` integration: both new tools appear in
  `tool_definitions()` when enabled and are dispatchable through `execute_tool` by name

## Technical Constraints

**Language:** Python; changes confined to `local_agent_runner/tools.py`,
`tests/test_tools.py`, `tests/test_check_transcript.py`

implementation

`write_file`'s parent directories only; `list_dir` never creates anything
**Testing:** pytest, fully offline; `tmp_path` fixtures
**Environment:** must run inside a container (CONTRACT.md §10.3); no host-specific paths

## Notes

- Epic-level decisions settled in this spec (do not reopen without a spec amendment):
  - **`write_file` auto-creates missing parent directories** under an already-permitted
    resolved path — there is no separate permission knob for directory creation; the
    target path is the unit of permission checking, consistent with the other file
    tools.
  - **`list_dir` is non-recursive** — immediate entries only, token discipline (§6) over
    convenience; deeper inspection is a sequence of `list_dir` calls the model can make
    itself.
  - **`test_step` → `run_step` rename, not `return`→`assert` conversion** — the helper
    is a value-returning builder used by ~20 call sites; the fix is removing it from
    pytest's `test_*` collection pattern, not changing its semantics.
  - **`_TOOL_ORDER` becomes `["read_file", "write_file", "edit_file", "list_dir",
    "run_command"]`** — matches CONTRACT.md §4's table order; `git` is E2.2's addition.
