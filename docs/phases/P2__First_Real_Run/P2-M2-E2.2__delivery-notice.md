**Acceptance criteria evidence:**
- **A permitted subcommand actually runs, effect observable on disk:** `test_allowed_subcommand_commit_records_change_on_disk` runs `git add` then `git commit -m 'initial commit'` through the tool, then independently shells `git log --oneline` in the fixture repo and asserts the commit message is present — the effect is verified outside the tool call, not just via the tool's own reported exit code.
- **A denied subcommand returns a deterministic tool-error and never invokes git:** `test_denied_subcommand_returns_error_and_never_invokes_git` monkeypatches `subprocess.run` itself to fail the test if called at all, then exercises a denied `push` — the assertion would fail loudly if the permission check were bypassed or ordered after the subprocess call.
- **`git diff --exit-code` (non-zero exit) returns `ok=True` with the exit code visible:** `test_diff_exit_code_nonzero_is_successful_result` stages and commits a file, mutates it, then runs `diff --exit-code` — asserts `result.ok is True`, `"exit_code: 1"` in the output, and the diff content itself is visible to the model.
- **Fresh-clone, offline path:** no new dependency was added (`git` is assumed on `PATH`, consistent with the repo's own git-managed nature); `python3 -m pytest` from a clean environment needs nothing beyond `pip install -e ".[dev]"`.

**Test evidence:** `python3 -m pytest` → **190 passed, 1 skipped** (169 prior + 21 new) in ~1.3 s (Python 3.14.4, pytest 9.0.3, git 2.53.0); `python3 -m pytest tests/test_tools.py` → **68 passed** (47 prior + 21 new) in ~1.15 s. The pre-existing skip is the unrelated console-script-on-PATH guard from E1.x.

## Decisions settled during execution (per spec Execution Notes)

1. **Build order followed the spec's Execution Notes verbatim:** `ToolPermissions.allow_subcommands` + `subcommand_permitted` → `git` definition → `_git` handler → `_TOOL_ORDER` update → tests throughout.
2. **New message templates** (`_MSG_GIT_SUBCOMMAND_DENIED`, `_MSG_GIT_NO_SUBCOMMAND`, `_MSG_GIT_PARSE_ERROR`, `_MSG_GIT_TIMEOUT`) follow the existing module-level, template-string convention, mirroring `_MSG_COMMAND_DENIED`/`_MSG_COMMAND_TIMEOUT`'s phrasing style adapted for subcommands (e.g. "Only these allow_subcommands are permitted: {subcommands}", sorted).
3. **`_subcommands_text` helper** added alongside the existing `_globs_text`/`_patterns_text`, same shape: joins `sorted(permissions.allow_subcommands)` or falls back to a fixed `_NO_SUBCOMMANDS` sentinel — matches the spec's "permitted list (sorted)" instruction for the denial message.
4. **`_TOOL_ORDER` is exactly `["read_file", "write_file", "edit_file", "list_dir", "run_command", "git"]`**, matching CONTRACT.md §4's table order verbatim, `git` appended last.
5. **Test fixture repos are chdir'd into, not passed a `cwd` argument:** since the spec explicitly forbids a `cwd` permission knob and `_git` runs `subprocess.run` in the process's actual working directory (matching `run_command`'s existing behavior), every `TestGit` test uses `monkeypatch.chdir(repo)` (auto-reverted by pytest) rather than inventing test-only `cwd` plumbing in the handler itself.
6. **Pre-existing `test_tools.py` test using `"git"` as an example not-yet-implemented tool name was updated:** `TestToolDefinitions::test_unknown_enabled_names_ignored` used `"git"` (set up in E2.1, per that Epic's own Delivery Notice) as a stand-in for "a tool name in CONTRACT.md's table that isn't implemented yet." This Epic makes `git` a real tool, so the test's premise became false; it was updated to `"delete_repo"` (a name that is not, and never has been, a defined tool) — same pattern E2.1 used when `write_file` stopped being a valid "unknown tool" example. No assertions or coverage were removed, only the specific example name.
7. **No spec-settled decisions were reopened:** `shell=False` unconditionally for `git`; no `deny_subcommands` knob; first-parsed-token-only enforcement (no global-flag support); shared `timeout` knob (no second timeout permission); non-zero exit is a successful tool result.

## Out of scope (untouched, per Execution Contract)

- No `deny_subcommands` knob and no `cwd` permission knob for `git`
- No support for global flags or multiple subcommands ahead of the enforced first token (e.g. `git -C /other/repo status`)
- No SN-3 final-answer repair nudge (E2.3)
- No changes to `run_command`, `read_file`, `edit_file`, `write_file`, or `list_dir` handlers or message templates
- No network-reaching git subcommand (`push`, `clone`, `fetch`, `pull`) invoked in any test — exercised only as denied-subcommand cases
- No changes to governance documents, CONTRACT.md, or Milestone/Phase specs
