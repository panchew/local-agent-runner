## Decisions settled during execution (per spec Execution Notes)

1. **`write_file` success message:** `f"write_file: wrote {len(content)} characters to '{resolved}'."` — matches the spec's literal wording and the module's existing `f"edit_file: replaced 1 occurrence in '{resolved}'."` style (inline f-string, not a module-level template, since it is a single-shape success message with no denial variants).
2. **New message templates added** (`_MSG_IS_A_DIRECTORY`, `_MSG_DIR_MISSING`, `_MSG_NOT_A_DIRECTORY`, `_MSG_DIR_EMPTY`) follow the existing module-level, `{tool}: `-prefixed convention (module-level templates for determinism by construction, per the file's existing pattern for `_MSG_BAD_RANGE`).
3. **Argument-order in both new handlers:** required-string checks first (`path`, then `content` for `write_file`), then the permission check, then the existence/type check — mirrors `_edit_file`'s existing flow (all args validated before any filesystem check).
4. **`write_file` directory-target check precedes parent-directory creation:** if the resolved path itself is an existing directory, the handler returns the deterministic error before calling `mkdir` on anything — no side effect on a directory-target error.
5. **`list_dir` sort key is entry name** (`sorted(resolved.iterdir(), key=lambda p: p.name)`), then each entry rendered with a trailing `/` for directories — matches the spec's "sorted alphabetically" wording exactly (not full path, not case-folded).
6. **`list_dir` reuses `_cap_stream`** for its output cap rather than a second truncation implementation, per the spec's explicit instruction.
7. **`_TOOL_ORDER` is exactly `["read_file", "write_file", "edit_file", "list_dir", "run_command"]`**, matching CONTRACT.md §4's table order verbatim; `git` (E2.2) is not added.
8. **Pre-existing `test_tools.py` test using `"write_file"` as an example unknown-tool name was updated** (`TestExecuteToolSurface::test_unknown_tool_is_error_result` now uses `"delete_file"`, and the expected available-tools list was updated to the new five-tool order) — this test predates the Epic and asserted a fact (`write_file` is unknown) that this Epic's own deliverable makes false; leaving it unchanged would fail the DoD's "all unit tests pass" item. Likewise `TestToolDefinitions::test_unknown_enabled_names_ignored` was updated from `"write_file"` to `"git"` (E2.2's still-unimplemented tool) for the same reason. No test assertions or coverage were removed, only the specific example tool name each uses.
9. **`test_step` → `run_step` is a pure identifier rename:** verified by diff inspection — no reordering, no assertion changes, no other identifier touched in `tests/test_check_transcript.py`. The rename pattern used (`"test_step("` → `"run_step("`) was chosen because it matches the definition and every call site while leaving the unrelated real test `test_step_not_an_object_fails` untouched (confirmed: that identifier does not contain the substring `"test_step("`).

No spec-settled decisions were reopened (parent-dir auto-creation for `write_file`; non-recursive `list_dir`; the rename-not-convert fix; the new `_TOOL_ORDER`).
